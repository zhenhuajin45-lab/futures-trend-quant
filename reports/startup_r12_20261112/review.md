## 触发至最终副作用

1. `FiveRunner.__init__ → Process.start → clock_worker_started_monotonic`：首次等待从实际启动后的monotonic时刻开始，构造耗时不再占用。`supervise_clock → startup_wait` 仅允许存活子进程在首次合格前等待旧run/尚不存在的时钟文件；`runtime_clock_health.reason` 始终保留拒绝。当前run坏证明、缺manifest、权限错误、60秒截止或子进程死亡不获等待。
2. `PaperEngine.open → require_service(symbol) → health → 原风险/报价/截止 → persist intent → transport → paper_sim_bridge`：新政策先拒绝不合格服务，避免正常启动等待被订单路径写成持久停开；服务合格后仍独立严格查时钟。时钟故障由监督立即停开，健康恢复仍不清保护。原生再次检查时钟、同请求permit、服务身份、账户、报价、风险与原截止，任何一项缺失不调用柜台。旧政策分支保留兼容。
3. `paper_tq_feed → 同代health → consume → SOURCE_STATUS(False) → 逐品种禁开/候选失效`：缺初始输入时只保持自身NOT_READY，不造报价或bar、不生成当前信号，不创建订单。180秒只生成等待诊断；共享同代health必须真实继续推进且不超过原3秒。首份有效输入自然到达后仍走 `validate_envelope → tq_rows → merge_same_source → warmup_coverage → INITIAL_CACHE → 核心`。gap/修订/迟到/未来known_at继续原拒绝。
4. `paper_startup_r12_release.install`：严格停机、唯一当前宿主身份、实时空仓快照、无活动未知委托、代码/配置/私有seed身份及验证回执。大档案哈希后再次真实读取账户，再作最终停机/状态复核；仅原允许的读取证明和追加日志可变。保留账本、候选、墓碑、检查点、PA及pause/halt，仅迁移配置SHA和十个pin配置身份。

## 字段合同与不变门槛

新配置只增加 `clock_startup_policy`、`tq_input_wait_policy` 和 `notice_evaluation_policy`。主文件及配置产生新指纹；核心、方向/路径资格、账户SIM绑定、1手/2仓、风险比例、原30秒、3秒报价/服务、0.5秒偏差/0.1秒两源差/1秒RTT/90秒样本时龄均不放宽。原生执行仍需要完整symbol/side/price/stop/anchor、源代际和真实received_at、闭合证据、同请求WAL与permit；等待不生成这些字段。PA及背驰替代仅SHADOW。

源码审查覆盖 `open` 到意图/原生退出；测试以真实生产函数配合虚拟柜台实现，不登录或提交真实订单。软件验证及自然执行分列；最终数量、精确哈希及回执见 validation.json。

## 停机交接与恢复授权

覆盖由既有授权执行，但当前宿主运行时不覆盖。单次恢复必须新的明确授权、用户正常停止、空仓/无未知委托/健康门槛。为避免反复启动，可在用户明确授权后，对**已经实际加载并核验的R11**执行现有严格恢复，再安装仅启动生命周期增量R12，安装精确保留恢复后的执行状态；记录原R11宿主/停机/单次令牌与目标R12指纹。此路径不假称R12已加载，不复用此前令牌，任一门槛失败保持停开并报告。用户随后本人启动；如出现新的保护，再次授权独立处理。自动安装、时钟恢复和启动均不构成新开授权。

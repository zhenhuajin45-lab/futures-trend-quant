# R12 启动与逐品种输入等待合同

适用范围：R11 实际启动暴露的 D22、D23；不改变核心方向、PAPER_ENTRY_V5、PAPER_EXEC_V5、原30秒截止或账户/报价/风险/原生最终门槛。

1. `CLOCK_WORKER_STARTUP_WAIT_V1_20261112`：首次时钟等待60秒从时钟子进程实际启动后的 monotonic 时刻计量，独立于主机预热耗时。仅当前子进程存活、尚未取得本 run 合格证明，且文件尚未生成或证明明确属于旧 run 时，可以等待。等待期间证明仍不合格，服务和订单门槛均拒绝；绝不复用旧证明。当前 run 的不合格证明、子进程退出、等待超时立即持久停开。首次合格后任何后续时钟故障立即停开，不重新给予启动等待。恢复健康不清 pause/halt。
2. `TQ_INPUT_WAIT_V2_20261112`：每个品种无初始有效报价或闭合数据时保持 NOT_READY 并等待，不因180秒永久退出。180秒仅用于等待诊断。共享 publisher 必须继续提供同 run、同配置、3秒内的真实进度；错误/退出/陈旧证明仍拒绝。缺少健康文件仅在最初180秒等待。有效输入到达后走原同源 seed、闭合/修订/缺口、known_at、预热验证。无行情不展示信号、不提交订单；其它品种独立运行。
3. 启动期间订单先检查保守的共享服务及逐品种许可，再检查严格时钟；服务失败不写入订单WAL。后续原生仍独立检查真实时钟、服务、报价、账户、同请求permit与风险，不增加授权。
4. 兼容迁移仅配置指纹及十个 pin 配置身份更新；候选、意图、账本、墓碑、检查点、PA状态、pause/halt与历史保留。PA和背驰替代保持 SHADOW。
5. 发布、覆盖、实际加载、自然提交、成交退出分别登记。当前宿主运行时仅开发离线包，不热覆盖，不代启停。已消费的R11恢复授权不能复用；新增停开需要新的明确授权及停止/空仓/未知委托/服务/时钟核验。
6. `NOTICE_CAUSAL_PREFILTER_V1_20261112`：M15背驰提醒先按当前闭合柱、真实确认、cutoff及已消费ID筛选，再对待提醒事件做原实时行情检查。历史记录不得触发逐条行情证明读取。事件ID/去重及真实确认不变；TaskProgress仍记录真实完成，30秒门槛不变，不添加空心跳。

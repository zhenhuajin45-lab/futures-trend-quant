# R10 品种行情隔离：生产自审与交接

审查结论：源码和候选包按品种隔离行情准入；当前客户端尚未安装，运行效果、自然提交及成交退出仍待验收。采用单代理生产自审，未冒称独立审查或真实订单验证。

用户触发：一个品种没有行情，不应展示旧信号，也不应让独立健康品种因全池就绪检查失去信号与交易资格。当前 R9 曾发生 TQ 公共进程退出、TQ 五品种不可用而 GM 五品种持续接收真实行情的现场证据。其 ValueError 原因未完整保存，仍为 UNKNOWN；本次 NaN 机制回归不能倒推为该历史根因。

共享门槛保留账户 RECONCILED、新鲜 cash/positions/orders/active/fills、host_trade、唯一写入者、未知或其它活动意图、持久 pause/halt、组合风险、原生时钟。行情订阅、market/core 进度与故障、同代 TQ 证明和主力映射均按实际请求 symbol 校验。公共 TQ 进程故障影响它的依赖品种，不影响独立 GM 数据；GM 行情故障反向隔离。

`service_health.symbol_readiness[symbol]` 包含原请求 symbol、csymbol、ready、reason、checked_at 与源代际证据。最终原生出口仍需新鲜同 run/config 服务证明，并绑定同一正常 WAL 的 request_id、symbol、side、price、stop、path、core_evidence_id、evidence_id。其它活动意图、未知提交/撤单不能借此绕过。缺失、错品种、旧代或过期证明均拒绝。

行情就绪不是下单许可：状态改为 `ACCOUNT_READY_CHECK_EACH_SYMBOL`，另列 `symbol_entry_readiness`。盘前巡检输出共享账户与每品种检查；缺单品种仍报故障，不再伪装全池交易否决。盘前历史/订阅就绪不等于开市实时行情验收。

## 生产路径审查

1. TQ publish 每品种验证 metadata→quote→闭合输入；有限数值/字段错误只发布该品种 rejected 状态，其它品种循环继续。公共 API 初始化、连接或等待故障仍终止该公共源并留安全阶段信息。received_at 仅实际输入变化时更新，不以循环心跳伪造报价新鲜。
2. GM callback/轮询与 TQ 交接按 symbol 隔离错误、冻结与候选失效；坏行不会使下一品种行被跳过。无可信标的的 GM1202 撤销 GM 订阅证明，保留 attempted 集合，不自动重订；TQ 独立。共同存储或未知协调器系统故障仍保守阻断。
3. FiveRunner→PaperEngine 候选竞争→open→WAL→绑定 permit→原生 latest_quote→vendor submit 保留原风险、报价、数量、账户和截止守卫。实际引擎到原生 stub 回归覆盖 TQ 退出时健康 GM 多空请求，不能用 helper 通过替代此跨阶段检查。
4. M15 汇总/方向变化/背驰、候选卡、M5 监视器和 PA 本地候选卡均先检查本品种当前 session、新鲜真实报价及源/宿主代际。缺数或休市不展示旧方向为当前信号；M5 源迁移不补推迁移前事件。没有可用项时不发空汇总。健康品种不等待故障品种检查点推进。
5. 原始 facts、PA SHADOW、known_at 与历史事件仍保留；展示过滤不删除证据、不参与账户许可。已发生意图、柜台回报、成交/退出、持仓保护及故障通知保留，不因无行情隐藏已有暴露。

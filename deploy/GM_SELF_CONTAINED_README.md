# 客户端完整源码 main.py

`gm_paper_standalone_main.py` 是本轮交付，安装为客户端新建策略的 `main.py`。文件内嵌完整第一方源码和必要公共配置，按文件名分节保留可读原文：趋势及已闭合 H1、背驰、A/B/C/D 入场、动能／冷却、结构止损与 2R、按风险定手数、组合限制、D+1／休市纪律、模拟账户查询及开平撤、恢复对账、飞书卡片、标准 GM 生命周期。构建器为 `tools/build_standalone_paper.py`。

为满足 Python 多进程和隔离交易 SDK 的文件导入要求，主文件将内嵌源码按逐文件 SHA256 校验后写入**同一客户端目录**的 `_strategy_runtime`。项目根目录始终是该路径，忽略外部项目覆盖变量；运行依赖客户端目录自身的源码与状态。`_trade_env` 为同目录、相同锁定版本的交易 SDK 环境；数据 SDK、Python 解释器及常用库仍使用本机已有安装，未升级。

私有账户／Token／飞书配置在 `_strategy_runtime/config`；状态在 `_strategy_runtime/state/paper_observation_five`，证据在 `_strategy_runtime/evidence/paper_observation_five`。这些私有文件不嵌入公开源码。首次安装须保全原账户、账本、五品种检查点、通知 outbox 和资金基准并验证配置指纹；不能用空白状态替代恢复。更新主文件前也须先处理持仓和活动委托。运行脚本不会自动把停开状态清零。

在客户端选择实时运行，或在该客户端策略目录执行 `python main.py`。账户仍强制绑定专用期货模拟账户，MODE_LIVE 仅是实时事件模式，实盘关闭。普通隔夜、D+1、周五日盘和长休市前清仓、每笔 1 手、同品种不加仓、组合 2 仓等规则不变。

离线验证可执行 `python -X utf8 -I main.py --self-check --check-config`：不访问账户、不下单，检查嵌入源码、核心摘要和私有配置。仅复制主文件到新空目录时，可先运行不带 `--check-config` 的自检。真实运行还必须具备原本机认证、隔离交易环境和完整恢复状态。

本轮回归在隔离 Python 进程中，先固定 futures_trend_quant、backtest、tools 三个包到主文件释放的目录，再运行原 162 项定向测试，并逐模块检查导入来源。全部通过；没有让原 E 项目偷偷补齐缺少的模块。首次隔离回归发现旧 CLI 契约所需入口未包含及默认 GBK 的测试读取问题，补齐入口、显式 UTF-8 后原测试通过，未削弱策略保护或跳过失败项。

主文件自身逐进程设置 UTF-8 子进程协议，防止客户端启动时中文错误／回报在交易桥两端编码不一致。原型薄入口保留在历史版本，本文件是完整源码交付。停止客户端仍不等于已平仓；必须核对敞口和未完成委托。真实持仓中重启、带敞口强退和真实可成交性尚未实测。模拟观察不证明盈利能力，独立研究不重开。

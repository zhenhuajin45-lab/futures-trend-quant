# 五品种15分钟趋势通知

2026-11-05 北京时间部署。品种固定为豆粕、黄金、乙二醇、鸡蛋、红枣。

## 行为

- 有交易小节结束的 M15 时点后，等待核心完成本根判断，再汇总五品种；通常在收盘后15秒起发送，最迟90秒后带缺项标签发送。整点无活动小节时不刷屏。
- 卡片展示实际合约、偏多/偏空/未确认、判断截至时间、入场未成立或被拦截原因、离场确认票与禁入方向。对应信号记录齐备时附 M15 收盘、EMA34、斜率与趋势层 H1。
- 鸡蛋和红枣夜盘休市，明确沿用最近已闭合日盘判断。执行状态或本轮核心陈旧时标为历史记录；缺失、未来时间戳及检查点不一致时方向为未知。
- 已确认的趋势变化继续由 `paper_five.py::core_events` 的 `result.trend_changed` 立即发“趋势方向变更”卡片，附旧→新方向、M15 收盘时刻、规则依据。使用原来的闭合 M15 和确认机制，不把待确认反转当成已确认，不等15分钟汇总。不声称已经观测到实际反转。

## 运行方式与边界

`tools/paper_trend_notify.py` 部署到掘金客户端 `ops/trend_notify.py`。客户端 `_strategy_runtime` 仍为唯一策略运行根；此程序只读取核心检查点、状态、日历和信号日志，将卡片加入既有私有 `FeishuOutbox`。不调用 GM 行情/交易接口、不申请第二交易控制器、不改变账户、参数或风控。

```powershell
python -X utf8 .\ops\trend_notify.py
```

从其他目录运行须传 `--client <客户端绝对目录>`。Windows 文件锁防止重复通知进程；每根 M15 固定 outbox key 防重复卡片。HTTP 超时维持既有 UNKNOWN_DELIVERY 语义，不宣称端到端严格恰好一次。

这是独立通知进程，交易主进程不依赖它。重启电脑或通知进程退出后须另行启动通知程序，不能仅凭交易主进程存活推定趋势提醒正常。健康记录为 `evidence/paper_observation_five/trend_reminder_health.local.json`；逐卡依据在 `trend_summaries/`，实际投递回执在 `notifications/`。原始记录及私有配置只保留本机。

## 验证

`python -X utf8 -m pytest tests/test_paper_trend_notify.py tests/test_paper_notify.py -q`：20 passed。覆盖闭合柱对齐、缺失和未来检查点、陈旧状态、核心落后、去重及不修改策略检查点。Windows 默认 GBK 运行旧通知测试会在未指定 encoding 的测试读取中失败，按与运行端一致的 UTF-8 模式复跑通过。

实际 21:15 汇总卡片：SENT，vendor_code=0；豆粕偏空、黄金偏多、乙二醇偏空截至21:15，鸡蛋偏空、红枣偏多截至15:00并标注休市。首次快照亦已发送。21:22 核对仅一个通知进程，主策略仍为 NATURAL_SIGNAL_OBSERVATION、5品种就绪、账户 RECONCILED、pause_new=false；主入口 LF 指纹保持不变。

本次修改不触及开平仓代码，不重新打包或重启交易主入口。通知已投递与策略有效性、已有成交是不同事实。

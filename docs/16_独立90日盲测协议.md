# S0、EMA34_CONTROL、历史 A 的一次 90 日前向复验

主要问题是 A 能否在新行情中更早跟上同一段转折，同时减少错向时间并增加新方向参与。以 52301f1 的 A 离场代码为研究对象。三个对象共用截至当时可知的连续行情，S0/A 共用修正后的入场授权。技术候选使用无仓位、无成交回写的事实回放。

## 入组与开盲

机器锁见 `config/forward_v3_lock.json`。锁文件给出北京时间、代码及策略配置摘要、12 品种与事实版本。归属同一交易日的所有品种中，取首段开市时间最早者。冻结后第一个首段完整的期货交易日为第 1 天，第 90 天最后一段收盘时固定结束。实际日期由授权交易日历确定。协议冻结时已开始的夜盘计入预热。数据负责人每天提供可信日历和实际合约行情，未取得映射发布证据的行标记 UNKNOWN。

预热从真实历史重新推进。每品种要求在第 1 天前至少 1,200 根 M15，导入包含夜盘的完整 M1，聚合至 M5/M15。预热的信号和候选从计分中排除，已在预热首次出现的证据以后再出现也单列。评分键为 `(csymbol,eob)`，日期严格晚于旧研究窗终点 2026-11-02，评分时逐品种校验预定收盘钟。新首触标签只向评分区内取未来 48 根，旧窗标签、已评状态和事件不作为新输入。若须做历史外部复核，另登记候选唯一连续区间、各品种上市期、曾查看/样例清单、标签尾部净化及交集证据。

按完整性分层。日常导入仅记录完整性、行数与摘要。缺来源、缺交易日、缺合约、关键时点未知、评分 M15 键缺失或跨合约混合的评分 bar 为 DATA_BLOCKED。输入合格但完整事件不足 300 或关键品种无完整事件时，统计判定为 INCONCLUSIVE，届时封存。统计程序按固定 90 天一次运行。

## 手工输入

本机旧缓存缺少严格可得时钟，当前还不能满足首日前的历史预热。须补齐该固定起点之前各品种的授权预热包和日历。若最终仍缺证据，登记该固定窗口为 DATA_BLOCKED；首日和第 90 日均不顺延。

每个交易日一个目录，预热包格式相同。时间戳统一带 UTC 偏移，以交易所交易日归属。每份日包保留三个文件。

| 文件 | 必需字段及含义 |
|---|---|
| `sessions.json` | `date,previous,source,products`。previous 是上一个实际开市交易日，source 为数据负责人核验的交易所日历/停市版本。products 的键为 12 个 csymbol，值为按时间排序的 `[[开段时间,收段时间],...]`。每段枚举 (开段,收段] 全部 M1 收盘。授权来源独立于当日收到的行情。 |
| `mapping.parquet` | `csymbol,trading_date,symbol,known_at`。symbol 是实际合约，known_at 是主力选择或修订首次可知的时间。不能以交易日零点、事后导出时间补记。 |
| `quotes.parquet` | `csymbol,trading_date,symbol,bob,eob,available_at,open,high,low,close`。实际合约每分钟一行，切换前保留同一时点两腿报价，尽可能延续旧腿至候选后 8 根。可含 volume/amount/position。`available_at` 是真实观测时点。 |
| 独立日历对账清单 | score 时另传 JSON，含非空 `authority,version,session_sha256_by_day`。最后一项由数据负责人从独立核验的日历导出，覆盖预热至第 90 天各 `sessions.json` 的原字节 SHA256。 |

数据负责人需连同时间来源保留原始发布记录。校验摘要证明交接文件一致，来源可信度仍由数据交接记录支持。有独立实录的分钟决策时钟时，所有合约在同一 eob 附带相同的 `decision_at`（从该分钟收盘起至下一分钟收盘前）。否则整份输入使用名义 eob 为决策时刻。只接受决策时已经到达的报价；换月映射与同步价差仍须在生效分钟开始时可知。首次机会同时记录收盘时间和实际可知时间。

从项目根目录手动执行。仓库忽略 `data/cache/`，完整日包、行情、逐根结果均存本机。

```powershell
python -m backtest.forward_v3 prepare --study data/cache/forward_v3
python -m backtest.forward_v3 ingest --study data/cache/forward_v3 --bundle E:/授权日包/YYYY-MM-DD
python -m backtest.forward_v3 score --study data/cache/forward_v3 --calendar-manifest E:/授权日历/90日清单.json
```

先逐日导入连续预热包，再逐日追加评分包。相同内容重复导入返回 ALREADY_INGESTED，冲突修订会拒绝。中断残留的 `.ingest_in_progress` 须先核对其 PID 无写入者、已封存日包及摘要一致，再由操作员解除。评分前缀不满 90 天返回 READY_FOR_DATA。无法证明版本完整时保留故障状态和原包。完成开盲后同一研究读取既有结果。

## 计分与交付

价格路径有三个时间锚。公共参考转折的确认收盘用于描述市场已经走过的幅度。每组在段内首次被观察到连续两根同向时，用第二根收盘独立统计后 8 根，另计尚未跟上和尾部缺窗。入场机会取首次证据所在的 M15 收盘价，记录收盘后价格路径及真实可知时间。若下一根 M15 已在可知时间之前开盘，其高低价的先后无法还原，该行保留收盘锚观察，排除于可知后空间的分布。M15 动能门开、关分别列路径形成及接受次数，反转路径可以在门关时出现。

1. 用 ATR_DIRECTIONAL_CHANGE_V1 配对同品种同 event_id。有效段终点取下一次反向确认的前一根或未来 48 根的末端，先到者为准。两根新方向状态都落在段内、首根延迟 ≤4 才算及时。输出 A 救回数、伤害数、净差/完整事件数，及旧方向、新方向、none 的根数与占比。尾部截尾单列。
2. 以所有固定交易日建立面板，零事件日也保留。各品种共享同一组从连续交易日选取的移动块，按确认交易日整组重抽。主区间为 5 日块、10,000 次、种子 20261103、百分位双侧 95%；另报 10 日块。A 净及时率为正、5 日区间下界大于 0、10 日点估方向一致、错向占比降低及新方向占比增加，且样本容量、覆盖合格，记 LOCAL_REPLICATED。若主区间跨零记 INCONCLUSIVE；主区间整体落在零以下、敏感性同向则记 NOT_REPLICATED。单独报告两种设置及有效重抽次数。
3. 三组保留未来首触方向 ≥60%、≥2 ATR 趋势段覆盖 ≥70%、震荡切换 ≤1 次/品种日、独立事件延迟中位数 ≤4 根的门槛。保留原始分母、标签多/空/无触及/同根双触、零延迟、方向翻转及 none 比例。记录极值至确认已经走出的空间与确认后 8 根两侧最大空间，均以确认时已知 ATR 标准化，顺逆两侧最小为 0。
4. S0/A 记录授权、动能、M5/M1路径形成、锚点、接受/拦截与首次证据。各路径自有的动能/M1条件保持原状。按品种、方向、路径及 trigger 的 evidence_id 去重，记录首次已知的收盘时点和重复次数。同一证据在两组可能首次出现于不同收盘。各自用该时点实际合约的收盘、同合约后 8 根原始高低、当根 ATR 分别报告两侧空间与范围。换月、缺实际合约 bar、尾端不足、同根双触（上下各 1 ATR）分别标记。
5. `unblinded/groups.json` 为三组趋势结果，`events.json` 为配对及确认价格路径，`opportunities.json` 为共有与独有机会及实际合约价格路径。决定与运行身份见 `decision.json`。两腿原始价格和生效时钟保存在本地 `rolls.json`，产物摘要保存在 `checksums.json`。局部复现和趋势四门槛分层判定。局部复现且整体未达标时离场研究结案，后续若立项，优先评估建势与方向授权。全部通过时另审相对简单基准的增量与机会价格空间。费用与执行仍由 Gate 4 和 Gate 2 管理。

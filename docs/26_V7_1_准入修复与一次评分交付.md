# V7.1：准入修复与一次评分入口

2026-11-04，北京时间。基线 `375d9c42bb9500635a3067e8163d601ea5babbb7`。真实研究状态保持 **READY_FOR_DATA**。本轮交付准入反例回归、十二品种逐腿缺口、合成数据三层评分表；**没有执行真实独立样本评分**。

验收依据：[用户指定的 V7.1 任务书](tasks/V7.1_独立样本准入与一次评分_Codex任务书.md)。

旧窗等尺度诊断结案：原 2,493 对中净少 94 次明确目标先达，差 −3.77 个百分点，M5 提速停止。本轮不改该报告、不在旧窗运行首次筛选、不碰正式 90 日原料、协议或 score/seal 操作。结构止损、首次名额消费、匹配、研究门槛和 `execute_enabled=false` 保持原口径。

## 一、准入修复

三个评审反例在修改前均真实跑红，保存了命令及 `3 failed` 输出摘要；修复后旧入口和新入口都使用 V7.1 检查。旧入口 `tools/first_entry_v7/run_selector.py` 是兼容封装，不再保留能跳过准入的旧实现。

| 缺口 | 修复后的独立依据 | 失败边界 |
|---|---|---|
| manifest 能缩窗、平移、删日 | 在不读取价格标签的情况下，从授权 GM 日历固定四所各 73 个评分交易日；独立样本锁再绑定逐品种全部锚点、日历及来源政策、输入和代码哈希 | 首尾、任意中间日、标签上限、来源政策或锁哈希不一致，在打开回放前失败 |
| 稀疏 schedule 能冒充完整预热 | 由独立日历的逐自然日开闭市记录、历史夜盘归属和标准交易小节生成分钟分母，逐行对照供应商 schedule，再核对 raw | 只保留每桶末分钟，即使 raw 同样稀疏，也不能得到完整 M15；重复、错位、停休市外记录均拒绝 |
| 只有 header 的回放能成功 | 按品种、交易日、冻结应选腿构建应处理 M15 集合，并对照实际和合格帧 | 空回放、缺一个应选帧都失败，不生成选择或评分成功回执 |
| 应选完整腿误标 False | 从独立映射和时钟推导应选状态，双向检查缓存 `selected` | True 标错和 False 漏标都拒绝 |
| 未选腿提前影响全池 | 逐腿以它**首次应评分锚点**验证向过去 1,200 根完整 M15；不使用全池第一天作为所有腿共同起点 | 未选腿可继续预热；成为应选腿时仍不足则阻断，不能借另一腿数量 |

原价须含一致的 `symbol`、唯一单调且有时区的 `bob/eob`，并满足 eob−bob=60 秒；保留原始零成交分钟，不用补价制造完整性。真实包还必须有已冻结的上市/退市元数据，拒绝上市区间外行情。每腿首次应评分前检查最近 1,200 个应有 M15 桶均完整，不能拿很早的零散完整桶掩盖近期预热缺口。

当前固定池标准日盘为 09:00–10:15、10:30–11:30、13:30–15:00。有夜盘品种按其经过核验的结束时刻建钟；周一夜盘起点使用前一开市自然日，例如周五，不能机械减一天落到周日。节假日不进行夜盘的记录必须有历史依据。未登记的短小节直接拒绝，不自动把部分分钟算作完整预热。

### 锁与证据的层次

`config/v71_trade_date_lock.json` 只固定 73 个交易日，**不是实际日历和数据已经合格**。真实样本锁 `config/v71_sample_lock.json` 仍为 READY_FOR_DATA；当前无法凭该文件开始评分。

真正冻结前，日历包须分别带四所覆盖 2025-06 至 2026-05 的日历、历史小节和节假日夜盘依据及原件哈希，不能只填写一个自述“已核验”。随后 `freeze.py` 绑定完整分钟钟、所有评分锚点、来源政策、实际文件摘要，以及冻结生产核心和研究代码的文本指纹。准入重新生成锚点，与锁逐项核对。manifest 不能自行删日，也不能用自己的稀疏 schedule 重新定义分母。

代码锁同时包含复用的 V7 `selector.py`、`symmetric.py`、提供 tick 的 `config/fees.json` 和独立交易日锁，避免只冻结新模块却遗漏实际参与选择、比较和取整的依赖。它们仅做指纹绑定，本轮未改原内容。

工程夹具使用明确的 `ENGINEERING_FIXTURE_ONLY` 目的及显式 `--fixture`；它走同一个日期、时钟、raw、回放和覆盖检查入口，但合成日历不冒充真实官方历史证据。真实和夹具标记混用会失败。夹具的交易日历故意是合成工作日日历，覆盖同一登记首尾和全部 12 品种，总计 21,760 根应处理 M15；这不是实际 73 日行情的分母。

## 二、逐腿数据实物与缺口

本轮授权 GM 元数据查询得到：四所评分期均为 **73 个交易日**；按“上一完整交易日主力”研究代理，固定窗口共涉及 **29 个实际合约**。完整目录见：

- `reports/v71_actual_leg_data_gaps.csv`：逐品种 × 实际合约的上市区间、首次/末次应选日期、分钟和预热缺口。
- `reports/v71_actual_leg_data_gaps.json`：同表及每腿估计仍缺的交易日清单。
- `reports/v71_source_supply_checks.json`：本轮时钟小包和既有授权环境检查回执。

对首批 12 个实际合约，EDB 小包仅请求 `datetime_nano,volume`，不展示评分窗价格：2025-12-15 全部 HTTP 200，各 6 条；2025-09-15 全部 HTTP 403。使用原 V4 的 `normalize_edb` 将起始时间转换为 eob=开始+60 秒。合计收到 72 条预历史时钟/成交量采样，均不足一个完整 M15，也没有完整 OHLCV。

此前的 CF605、CJ605、m2605 在 2026-01-05 各有 6 条原价采样，目录照实记为已取得 18 条，而不是写成零；同样没有完整 M15。29 腿已证明合格的预热数量仍各为 0/1,200。

| 首批实际合约 | 估计最早需补的 M1 eob | 当前免费一年内的完整日上界 | 已证明合格预热 |
|---|---|---:|---:|
| CF605、SA605、SR605、eg2605、m2605、v2605 | 2025-10-20 14:01 | 各不超过 966 根 M15 | 各 0/1,200 |
| CJ605、jd2602、lh2603、lc2605 | 2025-09-03 09:01 | 各不超过 630 根 M15 | 各 0/1,200 |
| ag2604、au2602 | 2025-11-15 02:16 | 上界 1,554，尚未证明实际可完整取得 | 各 0/1,200 |

**上表日期只用时段代理估计缺口，不是正式准入时钟。** 上界还把免费边界当成完整交易日，实际可能更少；按当前标准小节口径，966/630 已低于 1,200，首批十个合约不能仅靠当前免费一年范围补齐。AU/AG 的上界较高也不代表其原件、夜盘和完整性通过。全部后续换腿的首次时刻、上市日和缺口日期均在逐腿目录中。

EDB 官方说明免 token 的分钟数据范围是滚动近一年，较早分钟需相应权限；这与本轮 403 一致，但不等于这些历史不可恢复。[EDB 官方文档](https://doc.shinnytech.com/edb/latest/md_server.html)

当前进程没有 EDB/Tq 认证变量或 BigQuant token/API key。本机另有此前保存的 Windows DPAPI 加密凭据；仅在内存解密并向 EDB 官方认证接口检查，返回 **HTTP 401**，没有取得历史授权。未采购、未开新账号、未把聊天凭据写入代码；网页登录或天勤试用不被当成已经取得 EDB 历史权限。历史 `available_at` 与映射 `known_at` 仍为 UNKNOWN。

**下一项材料**：按 CSV 的具体腿和缺口区间提供合法历史 M1 原件或可用的既有历史授权，另交历史时段/节假日依据和非本轮评分期的来源校准。来源、映射代理、数量单位、零成交及夜盘归属先冻结，再全池导出；不择优补价、不改用复权主连。材料齐备前保持 READY_FOR_DATA，不移动 1 月 5 日至 4 月 24 日的窗口，也不删品种。

## 三、一次评分入口与三张表

顺序固定为：

1. `admission.admit` 校验全部原料、时钟、锚点和回放覆盖。
2. 在闭合 S0 核心输出上复用原 `extract`、原结构止损和原首次筛选器，生成全量 S0 与每段首次。
3. 普通时刻在全体 S0 上无放回匹配一次；固化全量、候选、段身份、控制时点和键哈希，写选择回执。
4. `score_once` 先验证这些文件未变，再独占写 `once_claim.json`；真实研究还按 V7 登记哈希写本地研究级 claim，更换输出目录也不能重开同一登记。随后才调用原 `label_opportunity` 读取未来首触。已有 claim 不能再次评分；中途失败保留 claim，须另行审计处理。
5. 输出三张派生表和裁决，原价及含原价的完整标签仅留本机。

| 表 | 风险口径与主要字段 |
|---|---|
| `opportunity_table.csv` | 每个全量 S0 键及首次选择理由；原结构止损与对称尺度的明确目标、止损、双触、无触及、删失、开盘无效和完整标记 |
| `episode_table.csv` | 捕获/错过的完整有效段；段首/段末是否已知；左删失、预样本已消耗、开放末段、机会不可判定分开列 |
| `ordinary_pair_table.csv` | 原固定对照键/时刻、是否匹配、双方完整与各自对称 1.5 ATR 首触；候选只取原配对子集，不重新匹配 |

机会主比较使用原结构风险，下一合法同腿 M1 开盘作为价格代理；普通对照双方各自用其闭合 ATR×1.5，保持同样的 tick 外取整。首次开盘无效或未来不完整仍占用名额，不能递补。统计和选择之间没有根据标签改选的分支。

48 根静态价格路径保持原定义。逐机会另列标签窗是否越过段末、入场是否已到段末之后、首触是否发生在段末之后；段末未知时保留未知，不计作否。段表提供已知起止时刻供交叉核对。这些字段只解释跨段路径，不按未来结果改选，也不把静态目标先达解释成实际趋势离场后的成交收益。

嵌套候选/全 S0 在同一交易日块内同时重算比例，5/10 日、各 10,000 次、种子 20261104。机会层同时报告已完整分母、双触与所有信号槽位的删失界；段层报告完整有效段、容量区间和边界段敏感性；普通时刻除完整配对区间外，还检查所有已匹配机会的最坏删失界。不能仅删除坏掉的未来窗获得漂亮成绩。

门槛沿用 V7：质量至少 +2 个百分点、5 日下限 >0、10 日方向一致；有效段至少保留 50%；普通匹配覆盖至少 70%，且对普通时刻的 5 日下限 >0。质量或容量明确失败归档；删失界改变门槛或精度不足则证据不足。极少事件会使部分块重采样没有分母，这时不能把剩余样本的退化区间当成充分精度，裁决为证据不足，不另设或调优样本门槛。

合成表位于 `reports/v71_fixture_*`。本轮全池夹具中的机会是人为设定，全部输出标记 ENGINEERING_FIXTURE_ONLY，任何“通过/失败”均只说明评分器是否给出预期结果，不评价真实 S0 或首次筛选。

## 四、运行与状态

正式数据准备完成后的顺序示例：

```powershell
python -m tools.first_entry_v71.freeze --calendar <独立日历包> --input-root <快照目录> --output <新样本锁.json>
python -m tools.first_entry_v71.entrypoint --manifest <清单.json> --input-root <快照目录> --sample-lock <新样本锁.json> --output <新运行目录> --score
```

现有默认锁不合格，因此不会凭这两行命令开始真实评分。旧 V7 入口也接受同样参数并转到新检查，不能绕行。失败退出码为 2，诊断写为运行目录旁的 `*_failure.json`，不写成功选择回执。

| 状态 | 含义 |
|---|---|
| READY_FOR_DATA | 实包或真实冻结锁未到位 |
| DATA_NOT_QUALIFIED | 实包存在，但某项时钟、原价、预热或覆盖检查失败 |
| SELECTED_NOT_SCORED | 全覆盖通过，有机会且名单已固定，尚未读首触 |
| SELECTED_NO_OPPORTUNITIES | 全覆盖通过但策略确实零机会，与空回放明确区分 |
| SCORED | 一次评分已完成；是否有策略证据看裁决，不以生成表格替代门槛 |

定向命令、红灯复现、正常 CLI 正负例和逐品种覆盖汇总在 `reports/v71_engineering_checks.json`、`reports/v71_cli_checks.json`。真实入口链路已用合成件验证到最终回执；没有接入生产下单，不作生产就绪或净收益声明。

最终工程验收：**88 项定向测试通过（69 项逻辑与锁回归、19 项正常 CLI 用例）**。16 个 CLI 反例均被拒绝且未写成功选择回执；完整覆盖、完整零机会及延后换腿预热三个正例通过。合成覆盖为 12 品种、21,760 根 M15。冻结协议哈希和旧 V7 配对结果复核通过；真实新样本评分次数为 0。

首次全池夹具运行触及了 360 秒的工程测试护栏。随后改为逐品种生成、核对独立时钟，释放临时时段表并向量化分钟时间校验，全部通过后再核对完整全局锁。准入只保留已核验路径和紧凑时钟，选择表固化后评分逐腿重核哈希、读取原价；测试护栏调整为 900 秒以容忍本机负载。初次尝试及最终重跑记录均保留，数据和评分门槛没有放宽。

早期一次通过的 CLI 产物曾因使用 pytest 临时目录，被后续测试自动清理。因此最终验收在项目内 `data/cache/v71_cli_persistent_final` 重跑，机器报告从该持久目录的实际回执和最终 JUnit 生成，没有用旧测试摘要补造产物。

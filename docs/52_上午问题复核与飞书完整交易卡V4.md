## “有候选、没有价位”的实际原因

本机保存的25份候选详情回执中，9份形成价位，10份因 `ANCHOR_NOT_SAME_SIGNAL_BAR` 缺少原根锚点，6份被标记 `STRUCTURAL_STOP_INVALID`。这些是本机派生回执统计，不是外部独立复算。

旧详情进程在信号产生之后，再读取会继续前进的 `core_checkpoint.json`，因此会丢失原根结构；此外，结构本来就不合格的消息仍使用“入场候选·价位与时效”标题，混淆了资料缺失与交易资格失败。

本轮直接在实际 `FiveRunner.core_events` 消费结果时保存 `candidate_plan`：同根结构锚点身份、ATR、合约tick/乘数、当时已收到的报价、原始截止、规则和价位。不会在下一根checkpoint上补算，也不会调用交易接口来生成提醒。

## 新消息合同

| 消息 | 必须表达 |
|---|---|
| 🟦 入场候选 | 实际合约、红多绿空、参考入场价、止损、2R目标、1手风险、风险预算、剩余秒数、原30秒截止、具体路径及等待/停开原因 |
| ⛔ 信号拦截 | 具体失败原因；结构失败时显示锚点、ATR、结构距离/允许上限，止损目标标为“未生成”，不再叫有效入场候选；超预算也明确禁止开仓 |
| ⚪ 信号观察·待报价 | 可以展示信号收盘参考计算，但明确没有合格可成交报价，不当作可执行价格 |
| 🟦 入场委托·待受理 | 本地已持久化的实际限价、止损、目标、风险和有效期；不冒充柜台已受理 |
| 委托已受理 | 明确平台受理、限价及开仓保护计划；尚非成交 |
| 入场/离场已成交 | 实际成交价、手数、平台扣费及该笔交易自己的保护价位/清仓截止；不借用同合约后来一笔仓位的止损目标 |
| 候选终止·未下单 | 过期、失效、停开等具体原因；明确不续期、不补历史单，不再提供新的开仓建议 |
| 退出待完成/柜台确认已平 | 发令、成交、余量对账分开；没平完的风险不按零处理 |
| 日盘收盘账户摘要 | 账户权益与联调/未平估值边界；自然策略已平笔数、毛损益、平台扣费、扣后额、连亏与冷却分别展示 |

同一候选只发一张完整卡，取消“基础候选＋价位补充”的重复投递。本地趋势变化源记录只供优先提醒进程读取，最终只发一次带特别标识的反转/结束提醒。所有标题仅一个“截至 YYYY-MM-DD  HH:MM:SS”；价格与EMA显示两位小数，平台成交和本机接收时点统一北京时间。原始精度仍保存在本机证据中。

候选价位是当时参考，等待期间价格变化后，实际委托仍经原执行器重新核验。发生实际委托时再发委托价位，实际成交后再确认保护；不会将三者混写。

## 投递、限流与失效

飞书官方说明自定义机器人请求体不超过20KB，并说明11232限流问题，见[官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。本项目继续使用更保守的19000字节本地上限，每组字段最多10个。

- 风险退出/反转优先，成交和受理其次，候选及汇总随后；同优先级按产生时间发送。
- 明确的HTTP429/11232限流最多尝试3次，保留重试与耗尽记录。已经记录为旧版拒绝的历史消息不重放。
- 候选在原截止后仍未开始发送，记 `EXPIRED_NOT_SENT`；不通过迟到提醒“延长”交易资格。网络途中送达时间不可保证，卡片仍明示原截止。
- 超大/非法报文记本地拒绝，不让发送进程被未捕获异常直接打退出。网络或响应结果不明仍保持 `UNKNOWN_DELIVERY`，不盲重试。
- 发送期间持续更新心跳；HTTP发送进程退出或健康陈旧时停止新开，已有仓位退出继续，禁止自动重启或解除保护。

## 验证边界

直接覆盖真实 `core_events → 冻结计划 → outbox → sender`，以及 `ORDER_INTENT/EXECUTION_REPORT → 卡片` 链路。合成回归包含正确多/空价位、错误侧锚点、距离超限、单手超预算、缺报价、checkpoint前进、暂停、重复详情抑制、旧仓位保护混用、过期投递、11232有限重试、未知投递不重发、报文异常和健康停开。

所有合成信号仅写临时目录，没有发送到真实机器人、没有测试下单或人工行情触发。发布时只发送真实运行健康消息。发布前后保持空仓及无活动委托；沿用同核心受控升级，保存完整回退包，五份核心checkpoint不改写。

执行与复核仍为同一AI自检；新版自然信号投递及成交表现仍须后续交易时段核验。旧19006缺原文、历史忙请求缺具体操作、供应端M1延迟分段时钟不足等真实缺口保留，不用测试数量替代结论。

## 发布前追加发现：宿主行情连接再次失败

V3运行实例在15:57—15:58多次回报1200，16:13:23回报1201，随后再次1200，保护停开已经生效。当前本机GM 3.0.186的 `gm/api/errors.py` 明确将1200定义为实时行情服务连接失败、1201为连接断开；不能把它们写成重连成功。账户RPC对账正常，也不能替代宿主行情连接正常。

本轮接入平台标准 `on_market_data_connected/disconnected` 及 `on_trade_data_connected/disconnected`，将连接服务、状态、实际接收时间和宿主run_id保存到运行证据；init前收到的连接事件也保留。完整main导出这些回调，确保GM实际注册。连接恢复只记录事实，绝不自动清除停开或风控。

受控恢复额外要求当前宿主run_id的行情连接确实为 `CONNECTED`。新版本首先保持停开验证；若连接检查不过，继续停开并交付故障，不用改卡片的通过结果替代连接验收。

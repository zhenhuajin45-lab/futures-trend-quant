# V5消息权限口径与背驰独立提醒修复

本轮只修展示、独立提醒与其本地行情读取，不改S0方向、A/B/C/D资格、MACD计算、结构止损、2R目标、持仓纪律、原30秒期限或账户风控。账户原有停开保留，不借通知修复授权新开。

## 为什么10:15的五品种卡片都写禁止新开

卡片顶部 `trend_risk()` 仍读取 `trade_permission` 这一背景技术门控，按旧全局口径输出“禁止新开”；下部解释层已经支持V5逐路径资格。两处表达不一致，容易把“A/C/D柱符号未同向”误读为“B也被同一条规则否决”。

用同一份10:15记录重排文字，[逐品种示例](../reports/notice_fix_20261109/card_text_examples.json)显示：菜油本根未形成有效路径；豆粕、豆油及棕榈的D未满足原条件；黄金没有S0方向授权。它们都不是已证实被MACD单独拦住的可成交B。除此之外，账户 `pause_new=true` 是单独的执行层限制，必须另列，不能与策略路径原因混为一谈。

新卡片分别显示背景、逐路径资格与账户执行状态。B的M15柱符号仅作提示，A/C/D保留硬门槛。无方向时不再把价格、斜率或动能相对一个不存在的授权方向作禁开解释。旧M15背驰从周期汇总的历史详情中移出；若它确实属于某条路径的拒绝理由，仍如实保留该理由，不能通过删文案改变交易政策。

## M5提醒为何没有及时出现

原独立模块已经存在，但运行日志持续出现 `M5_DIVERGENCE ValueError`。离线只读复现定位到 `LocalBars.load()` 的 `M1_REVISION`：模块误选最新下载的预热缓存，与较早观测记录混合。豆粕首个反例是11月6日15:00的成交量差异，价格字段一致。它不证明核心行情也出错；运行核心使用检查点绑定的种子。

修复后提醒读取同一检查点固定种子并核验路径、合约、截止及SHA256，再合并当时已取得的本地M1。OHLC冲突仍拒绝；纯成交量差异保留固定种子/首次观测并留证，仅计算价格型M5指标，不据此作成交量研究结论。固定种子存在时不以任意最新缓存替换它。

首次重启实测还发现：维护期间分钟可能只存在于当次暖机缓存、未写为新增M1日志。因此又补入与当前运行清单匹配的暖机缓存，只填缺口，不覆盖已固定价格；清单时间和本机文件可知时间均须不晚于检查时刻，输入逐文件验哈希。五品种价格序列与核心“固定种子＋本次暖机＋本次实收分钟”的合并结果逐项哈希一致，见[输入一致性复核](../reports/notice_fix_20261109/source_consistency.json)。中间版本未发出新的M5背驰提醒，也未发订单；最终以第二个发布包为准。

本机五品种原件均已完成独立加载、1200根闭合M5指标与原背驰函数检查；结果保留在本机 `evidence/notice_fix_20261109/local_source_probe.json`，未发送探测通知或订单。这个检查不是盈利验证。

## 新的提醒合同

- M5以完整已闭合柱为输入，仍调用策略原 `_latest_divergence`；每3秒通知循环检查尚未处理的闭合M5，资料未到齐时同一分钟可重试，不等待M15汇总。
- 新M5事件单独发卡，区分反向预警、同向结构和“方向未授权”。这只是观察范围与文案调整，不赋予任何开平仓权限。
- M15背驰仅在核心本根新确认时独立发卡；历史结构仍有效不重复当作新事件。
- 同一事件稳定ID去重，启动及重启截止阻止历史事件重新宣告。确认时刻与实际识别时刻分别记录，显示延迟；原枢轴确认所需的后续柱没有被取消，也没有改成M1背驰。
- 单个品种资料冲突不再中断其他品种检查。组件健康写明 `DEGRADED`、品种及原因，并单独提醒“不可用不等于没有背驰”。

策略的M5背驰仍需要枢轴确认，不能承诺极值出现瞬间知道。实际通知还受本地行情入库及飞书发送影响；轮询3秒不等于承诺3秒送达。

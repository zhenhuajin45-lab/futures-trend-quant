## 4. 成本 P0：从原件一直核验到最终裁决

原缺陷已在实际 `judgment()` 复现：其余合成指标全达标时，3 tick 实测成本或不匹配费率仍误返回经济性通过。两个回归用例修前均失败，修后通过。

当前路径为 `entrypoint.run → independent.execute → load_cost_contract → ShortSwingAccount → ledger_cost_coverage → cost_assessment → judgment`。

- `cost_evidence.json` 与 `input_lock.json` 绑定原始文件 SHA256、费用模型 SHA256；费率和报价原件都必须属于输入目录，来源人与复核人不同。`costs_certified=True` 及两个旧核验布尔标志本身不构成资格。
- 费用必须按实际合约和有效期覆盖评分期间；开仓、平仓、平今比例/定额与券商每手加收逐项对应账户实际费用公式。任何数值不匹配，返回 `COST_MODEL_REPLAY_REQUIRED`，不会拿参考账本直接签经济性通过。本轮未擅自替换实际费率或重跑新成本模型。
- 报价包含实际合约、交易日、交易小节、方向、手数、开平偏移、参考价、买卖一价及数量、tick、本机接收与报价时钟。报价必须先于决策可得且不超过 1 秒；对手量不足、错侧、未知时钟或晚到均待核验。
- 实测量为与账户原始价格代理比较的**最大不利 L1 可执行偏移**；手续费另计，不能在 tick 与费用中重复扣除。它是盘口代理，不宣称已实测真实订单成交。任一已验证样例超过每边 2 tick，预检返回 `INSUFFICIENT_COST_MARGIN`，在写独立检验占用标记前停止。
- 回放后逐笔核对 1/2 tick 两组账户全部开平两侧的合约、时间、同方向同手数、参考价与当期费率，期末未平仓也须核对已付开仓费；稀疏样例不能覆盖其他成交。缺任何覆盖，保持 `ECONOMICS_PENDING_COST_VALIDATION`，不签经济性通过。

协议仅增补工程成本合同并刷新源哈希；原协议完整副本在 `tools/same_discipline_v10/v9_protocol_before_cost_fix.json`。82 日集合、资金、15% 预算、持仓规则与策略账户代码均未改变。源资格仍阻塞，真实回放未运行，唯一独立检验未消耗。结项后不自动推进该版本采购或评分。
